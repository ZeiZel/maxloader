# Max Loader — спецификация Chrome-расширения

Статус: draft for implementation  
Дата: 2026-08-26  
Целевая платформа: Google Chrome, Manifest V3  
Целевой сайт: `https://web.max.ru/*`

## 1. Цель и границы

Расширение добавляет в панель действий режима множественного выбора MAX кнопку для последовательного скачивания всех файлов из выбранных сообщений. Проект должен быть реализован на TypeScript, собираться `tsup`, храниться в отдельном Git-репозитории и быть подготовлен к публикации в Chrome Web Store.

В первую версию входят:

- обнаружение режима выбора сообщений на `https://web.max.ru/*`;
- определение выбранных сообщений, содержащих скачиваемый файл;
- добавление одной кнопки скачивания в существующую панель действий;
- последовательная активация штатных кнопок скачивания MAX;
- корректное обновление и удаление собственной кнопки при изменениях SPA-интерфейса;
- сборка, тестирование, упаковка ZIP и подготовка материалов для Chrome Web Store.

Не входят: скачивание вложений через собственные HTTP-запросы, чтение содержимого файлов, объединение файлов в архив, обход авторизации MAX, поддержка других браузеров и доменов.

## 2. Источники и уровень достоверности

### 2.1. Требования пользователя

Пользователь запросил Chrome-расширение, которое реагирует на выделение сообщений, проверяет наличие файлов, показывает кнопку группового скачивания и последовательно инициирует скачивание всех файлов. Пользователь предпочёл TypeScript и `tsup`, попросил создать Git-репозиторий, разместить его в своём GitHub и опубликовать расширение. Для тестирования указан уже открытый чат `https://web.max.ru/0` и приложен скриншот с тремя выбранными файловыми сообщениями.

### 2.2. Проверенные DOM-факты

Эти факты получены при live-инспекции текущего интерфейса `web.max.ru`; они являются доказательствами для первой реализации, но не публичным контрактом сайта:

- выбранное сообщение имеет контейнер `.messageWrapper--selection`;
- файловая карточка внутри выбранного сообщения содержит `button[aria-label="Скачать"]`;
- кнопка-счётчик выбора является `button`, чей нормализованный `textContent` соответствует `/^Выбрано\s+\d+$/`;
- ближайшая панель действий содержит эту кнопку, а также кнопки с текстами `Удалить` и `Переслать`;
- в панели встречается сгенерированный класс вида `actions svelte-*`.

Классы `svelte-*` намеренно не используются: это нестабильные хеши сборки. Тексты русской локали тоже не идеальны, но являются наиболее устойчивым доступным признаком контейнера на момент проверки.

### 2.3. Разрешённый конфликт и допущения

- В исходном запросе указан домен `max.cum`, однако ссылка, скриншот и live-DOM относятся к `https://web.max.ru/`. Для реализации каноническим источником считается фактический ресурс: только `https://web.max.ru/*`. Домен `max.cum` не включается в permissions.
- Под «топбаром» понимается нижняя панель действий режима выбора, показанная на приложенном скриншоте, а не глобальная верхняя навигация сайта.
- Штатный `click()` по кнопке `aria-label="Скачать"` считается требуемым «событием скачивания». Расширение не перехватывает URL и не использует `chrome.downloads.download()`.
- В одном выбранном сообщении может быть более одной кнопки скачивания; первая версия скачивает каждую найденную уникальную DOM-кнопку в порядке документа.
- Интерфейс проверки ориентирован на русскую локаль из live-DOM. Изменение локали может потребовать новых устойчивых якорей.

## 3. Функциональные требования

### FR-1. Область выполнения

Content script запускается после загрузки DOM только на `https://web.max.ru/*` и остаётся работоспособным при SPA-навигации без перезагрузки страницы.

### FR-2. Обнаружение состояния

Расширение отслеживает изменения `document.body` через один `MutationObserver` с `{ childList: true, subtree: true, attributes: true, attributeFilter: ["class"] }`. Обработчик не выполняет полный пересчёт на каждую мутацию: изменения объединяются debounce-планировщиком на ближайший animation frame либо коротким таймером до 100 мс.

После каждого пересчёта расширение:

1. Находит все `.messageWrapper--selection`.
2. Внутри каждого выбранного контейнера находит `button[aria-label="Скачать"]`.
3. Находит кнопку-счётчик по нормализованному тексту `/^Выбрано\s+\d+$/`.
4. Поднимается от неё к ближайшему предку, который одновременно содержит кнопки `Удалить` и `Переслать`.
5. Синхронизирует состояние собственной кнопки без дублирования.

Для внутренних элементов расширения используются собственные атрибуты, например `data-max-loader-action`, а не классы сайта.

### FR-3. Кнопка группового скачивания

Если найдена панель действий и хотя бы одна доступная кнопка скачивания в выбранных сообщениях, расширение добавляет в эту панель одну кнопку перед системными действиями либо в конец группы, если безопасная точка вставки не определена.

Требования к кнопке:

- понятная подпись: `Скачать файлы (N)`, где `N` — число найденных кнопок скачивания;
- `type="button"` и доступное имя (`aria-label`);
- визуальное соответствие панели через минимальные собственные стили, без копирования сгенерированных `svelte-*` классов;
- отсутствие дубликатов после повторных мутаций и SPA-навигации;
- удаление, когда режим выбора закрыт, панель исчезла или ни одного файла не выбрано;
- обновление счётчика при изменении выбора;
- disabled-состояние на время выполнения очереди.

### FR-4. Последовательное скачивание

По нажатию расширение заново собирает актуальный список `button[aria-label="Скачать"]` внутри `.messageWrapper--selection`, а не использует устаревший список из предыдущего пересчёта.

Алгоритм:

1. Зафиксировать список уникальных, подключённых к DOM и не disabled кнопок в порядке `document.querySelectorAll`.
2. Заблокировать групповую кнопку и показать прогресс `Скачивание 0/N`.
3. Для каждого элемента проверить `isConnected` и доступность, вызвать штатный `element.click()`, затем выдержать задержку 300 мс перед следующим элементом.
4. Ошибка одного элемента не прекращает очередь: она записывается без приватных данных, после чего обработка продолжается.
5. В конце показать краткий результат (`Готово: X/N` либо `Скачано X, ошибок Y`) и при следующем DOM-пересчёте вернуть обычное состояние.

Задержка вынесена в именованную константу и может быть скорректирована после ручного теста. Параллельные запуски запрещены. Повторное пользовательское нажатие во время очереди игнорируется.

`element.click()` подтверждает только инициирование штатного обработчика сайта. Без permission `downloads` расширение не утверждает, что Chrome физически сохранил файл; системные отказы и запрос разрешения на множественные скачивания обрабатывает Chrome.

### FR-5. Ошибки и деградация

- Если панель не найдена, расширение не меняет DOM сайта и ждёт следующей мутации.
- Если часть DOM изменилась во время очереди, отсутствующие элементы пропускаются как ошибки.
- Ошибки логируются в консоль с префиксом `[Max Loader]`, без имён файлов, URL скачивания, текста сообщений и пользовательских идентификаторов.
- Расширение не должно ломать штатные действия `Удалить`, `Переслать`, снятие выбора или одиночное скачивание.

## 4. Архитектура и структура проекта

Предлагаемая структура:

```text
maxloader/
├── src/
│   ├── content.ts          # bootstrap, observer, reconcile
│   ├── dom.ts              # селекторы и чистые DOM-функции
│   ├── download-queue.ts   # последовательная очередь
│   └── styles.css          # изолированные стили кнопки
├── tests/
│   ├── dom.test.ts
│   └── download-queue.test.ts
├── public/
│   └── icons/              # 16/32/48/128 px
├── manifest.json
├── package.json
├── tsconfig.json
├── tsup.config.ts
├── README.md
└── .gitignore
```

Сборка `tsup` формирует browser-compatible IIFE без runtime-зависимостей и source maps в production-пакете. CSS и manifest/icons копируются в `dist/`. Обязательные npm scripts: `build`, `dev`, `typecheck`, `test`, `package`.

## 5. Manifest V3 и минимальные разрешения

Manifest содержит:

```json
{
  "manifest_version": 3,
  "name": "Max Loader",
  "version": "0.1.0",
  "content_scripts": [{
    "matches": ["https://web.max.ru/*"],
    "js": ["content.js"],
    "css": ["styles.css"],
    "run_at": "document_idle"
  }]
}
```

В первой версии не нужны `permissions`, `host_permissions`, `activeTab`, `tabs`, `storage` или `downloads`: точный host pattern уже задан в `content_scripts.matches`, а скачивание инициирует штатная страница. Если Chrome Web Store или фактическая реализация потребует отдельный `host_permissions`, разрешается добавить только `https://web.max.ru/*` с документированным обоснованием. Permission `downloads` допускается лишь при изменении архитектуры на прямой `chrome.downloads` API и требует отдельного пересмотра приватности.

Content Security Policy MV3 соблюдается: никакого удалённого кода, `eval`, inline-script или CDN.

## 6. Тестирование и проверка

### Автоматические тесты

DOM unit-тесты (Vitest + jsdom):

- распознавание выбранного файлового сообщения;
- игнорирование выбранного сообщения без download button;
- поиск панели по счётчику и соседним системным действиям;
- отсутствие зависимости от `svelte-*`;
- создание ровно одной кнопки при серии мутаций;
- обновление `N` и удаление кнопки;
- очередь кликает элементы строго последовательно и с задержкой;
- disabled/detached элементы пропускаются, ошибка не останавливает очередь;
- повторный запуск во время очереди невозможен.

### Ручная проверка в открытом чате

1. Собрать проект и загрузить `dist/` через `chrome://extensions` → Developer mode → Load unpacked.
2. Открыть/обновить `https://web.max.ru/0`.
3. Выбрать сообщения без файлов: кнопка Max Loader отсутствует.
4. Выбрать одно и несколько файловых сообщений: кнопка появляется один раз и показывает верное число файлов.
5. Изменять выбор: число обновляется, после выхода из режима выбора кнопка исчезает.
6. Нажать кнопку: штатные скачивания стартуют в DOM-порядке; системные действия панели остаются работоспособны.
7. Повторить после SPA-перехода в другой чат и назад.
8. Проверить светлую/тёмную тему, узкую ширину окна и русскую локаль.
9. Проверить поведение при запросе Chrome на разрешение множественных автоматических скачиваний.

## 7. Acceptance criteria

- На любом URL `https://web.max.ru/*` расширение не выполняется за пределами указанного origin.
- При выборе хотя бы одного сообщения с `button[aria-label="Скачать"]` в корректной панели показана ровно одна кнопка `Скачать файлы (N)`.
- `N` равен числу актуальных download buttons во всех `.messageWrapper--selection`.
- При отсутствии выбранных файлов собственная кнопка отсутствует.
- Нажатие инициирует один штатный click на каждую актуальную кнопку, строго последовательно, с паузой между кликами.
- Ошибка или исчезновение одного элемента не препятствует обработке остальных.
- Повторные мутации и SPA-навигация не создают дубликаты observer/button/event listener.
- Ни один селектор не содержит `svelte-*` или иной build hash.
- Штатные функции MAX визуально и функционально не нарушены.
- `npm run typecheck`, `npm test` и `npm run build` завершаются успешно.
- Production ZIP содержит только необходимые файлы из `dist/`, загружается как unpacked extension без ошибок и проходит ручной сценарий на тестовом чате.
- Репозиторий опубликован в аккаунте пользователя GitHub без секретов, локальных артефактов и персональных данных.

## 8. Приватность и безопасность

Расширение обрабатывает только DOM уже открытой пользователем страницы. Оно не отправляет телеметрию, не обращается к внешним серверам, не сохраняет содержимое сообщений, имена файлов, cookies, токены или историю посещений. Для карточки Chrome Web Store требуется короткое privacy disclosure: данные не собираются и не передаются; доступ к `web.max.ru` используется исключительно для добавления группового действия в интерфейс.

Нельзя логировать содержимое сообщений, download URL или идентификаторы пользователей. В репозиторий и пакет не включаются credentials, browser profile, скриншоты приватного чата и тестовые файлы пользователя.

## 9. Риски и меры

- **Изменение DOM MAX.** Селекторы не являются API. Локализовать их в `dom.ts`, покрыть фикстурами и документировать дату live-проверки.
- **Локализация.** Поиск панели зависит от русских текстов `Выбрано`, `Удалить`, `Переслать`. При наличии доступных aria/data-атрибутов перейти на них; до этого честно ограничить поддержку русской локалью.
- **Multiple automatic downloads.** Chrome может заблокировать серию и показать site permission prompt. Расширение не обходит этот механизм; пользователь должен разрешить множественные скачивания для `web.max.ru`. Это необходимо проверить вручную и описать в store listing/README.
- **User activation.** Некоторые сайты/версии Chrome могут принимать только первое программное скачивание из одного gesture. Проверить реальное поведение; если очередь не работает, архитектурное изменение выносится в отдельное решение, а не маскируется.
- **Rate limiting/SPA race.** Интервал 300 мс и проверка `isConnected` уменьшают риск; значение подтверждается тестом.
- **Store review.** Узкие permissions, отсутствие удалённого кода и ясное privacy disclosure снижают риск отклонения, но не гарантируют одобрение.

## 10. Git, упаковка и публикация

1. Инициализировать Git в корне проекта, создать осмысленные коммиты и GitHub-репозиторий в аккаунте пользователя; перед push проверить отсутствие секретов и приватных артефактов.
2. Выполнить canonical verification: typecheck, tests, production build и ручной smoke test unpacked-версии.
3. Сформировать ZIP из **содержимого** `dist/`, чтобы `manifest.json` находился в корне архива. Не включать исходники, tests, source maps, `.git`, `node_modules`.
4. Подготовить store assets: иконки, краткое/полное описание, screenshots без персональных данных, privacy disclosure, category и support information.
5. В Chrome Web Store Developer Dashboard создать новый item, загрузить ZIP, заполнить Privacy/Permissions/Distribution и отправить на review.
6. Публикация считается завершённой только после статуса Published/доступной listing URL; отправка на review — отдельная промежуточная стадия. Если аккаунт разработчика не зарегистрирован или требуется одноразовый платёж/подтверждение, это действие выполняет пользователь.

Загрузка в локальный `chrome://extensions` нужна для теста, но не заменяет публикацию в Chrome Web Store. GitHub push и отправка в Store являются внешними изменениями и выполняются только после проверки конкретного repository name/visibility и финального пакета пользователем либо в пределах явно подтверждённого выбора.

## 11. Открытые вопросы перед публикацией

- Название и visibility GitHub-репозитория (рекомендуется `maxloader`, public только после проверки отсутствия чувствительных данных).
- Публичное имя расширения, описание, язык listing и support URL.
- Наличие регистрации Chrome Web Store Developer и оплаченного регистрационного сбора.
- Подтверждение поведения очереди и оптимальной задержки при реальных multiple-download prompts.
- Нужно ли официально поддерживать локали, отличные от русской; первая версия этого не обещает.
